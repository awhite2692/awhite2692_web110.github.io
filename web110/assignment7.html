Internet Reference Models, TCP/IP, and DNS: One of the most interesting things about this activity was how much of the material connected to what I previously learned in Harper College's CompTIA Network+ class. The tutorials covered networking concepts such as the OSI Model, TCP/IP, Internet protocols, and the Domain Name System (DNS). I learned how these different components work together to allow computers and other devices to communicate over a network and access resources on the Internet. The OSI Model helps explain networking in separate layers, while TCP/IP provides the protocols used to transmit information between devices. DNS translates domain names into IP addresses so users can access websites without having to remember numerical addresses. Reviewing these topics helped reinforce my previous coursework and gave me another opportunity to understand how the different parts of networking fit together. I can apply this knowledge when learning more about networking and cloud computing, as well as when trying to understand connectivity issues with my own devices. Network Connectivity and Troubleshooting: Another important part of this activity was learning about the tools used to verify Internet connectivity and troubleshoot network problems. Commands such as ipconfig, ping, tracert, and nslookup provide different types of information about a network connection. Although I use a Mac rather than a Windows computer, the underlying networking concepts still apply. Tools such as ifconfig, ping, traceroute, and nslookup can help identify network settings, test connectivity, trace the route that information takes, and check whether domain names resolve to IP addresses. I found this useful because it connects the networking theory I learned in my CompTIA Network+ class to practical troubleshooting. At home, I use several Apple devices that connect to the Internet through my AT&T modem and router, using both wired and wireless connections. Understanding these tools could help me narrow down whether a connection problem involves an individual device, my local network, or communication with an Internet host. This knowledge could also be useful in future technical roles where understanding basic network troubleshooting is important. Comparing Internet Service Providers and Plans: The activity comparing Internet service providers reminded me of a situation I experienced at home several years ago. At the time, we were using an older DSL modem that eventually stopped working, and compatible replacement equipment was no longer available. We had to look into upgrading to a newer modem and router, so I researched the available options to determine which would be the least expensive choice. Because the building was older, getting Internet service through another option would have required bringing a dedicated line into the building, which would have added complications and costs. We ultimately found that staying with the existing service was the most affordable option, especially because we were combining telephone and Internet service. This experience helped me understand that choosing an Internet provider involves more than comparing advertised prices or connection speeds. Availability, installation costs, equipment requirements, reliability, and bundled services can all affect the overall cost and practicality of a plan. Different connection types, including DSL, cable, cellular, and satellite, have different advantages in terms of availability, mobility, bandwidth, reliability, and delay. The number of devices using a connection and the security of the service are also important considerations. I can apply what I learned when evaluating my current Internet service or considering a future change in providers. Rather than looking only at the monthly price, I can compare the total costs, connection performance, availability, and features of each plan to determine which option best meets my needs. This activity reinforced the importance of researching Internet options before making a decision, particularly when a building's existing infrastructure limits the available choices.
